# Michel's Life — Windows v3.0.218 + Android Direct v0.2.6

One **proposed** unified distribution with the current canonical Windows installer/portable package and a permanently signed Android Direct APK (versionCode 8). These are release notes for a candidate, **not evidence that a public build exists**.

## Android Direct v0.2.6 / versionCode 8

- Mobile-first Premium Contracts: compact disclosure and genuine saved category filters; responsive edit sheet and touch-size fields, including short keyboard-height layouts.
- Android Settings: compact phone navigation with real pane selection, including the full Settings category sweep.
- Weekly Review: readable contract and health rows and tap-friendly actions linking to the canonical Premium Contract board.
- Calendar: the selected day is preserved when switching between Month and Agenda.
- Achievements and Affirmations: mobile interaction and favorites/hide coverage.
- Quick Capture: real mission input and save while the editing viewport is short.
- Statistics and Compare: 320/360-pixel chart/card containment.
- A review gallery of Playwright Android screenshots accompanies CI evidence; it is not a screen capture from a physical Galaxy.

## Windows v3.0.218

- New packaged Setup and Portable to preserve the single unified release/update channel.
- Approved desktop visual themes, Chapter Scenes, fonts, backgrounds and branding remain unchanged.
- Installed Setup launch and Portable launch checks, bilingual/frontend smoke and SHA-256 checks remain mandatory.

## Integrity and known limitations

- Android Direct must be signed by the **same pinned permanent signing certificate** as v0.2.5 and have versionCode 8; do not substitute a debug APK or new signing identity.
- Android Direct is distributed separately from Google Play. Microsoft Store distribution is also separate.
- Full same-account Windows↔Galaxy Supabase sync, real Android soft-keyboard/gestures, locked-screen/Doze alarms and native installed Windows Home/About screenshot evidence are not certified by browser or emulator checks. Issues #28, #53 and draft PR #62 track these limitations.
- Native real-device visual approval is carried out on the released signed candidate; known blockers must not be represented as passing.
- Nothing is published simply by merging this preparation PR. Publishing requires an **isolated, explicitly authorized release-intent commit** and all exact-commit + native packaged CI/signature/digest gates.
