# Granada — alarm transactions and delivery ownership

New candidate prevents invalid/duplicate whole-list rows from deleting existing native alarms, and compares exact authoritative native registry bytes under the same lock before writing. WebView reads fail closed; stale delivery data cannot be reuploaded automatically. UI changes are limited to explicit errors, not layout. Native snooze claims the delivered occurrence, persists only its replacement, schedules it independently and rolls back on failure; a failed snooze keeps the ringing surface active. Android Activity tracks the alarm ID owning media and vibration, and does not dismiss unrelated alarms; a pending notification retries after dismissal. Browser tests exercise the real registry and snooze controller with injected failures; Kotlin structural contracts remain separate from actual physical QA. No live alarms or user data accessed. Partial scheduling failure for ordinary multi-alarm sync and OS process death during a write still need real device validation. No release.
