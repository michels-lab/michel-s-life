# Granada — Android Drive metadata concurrency

Local metadata previously used unguarded read/modify/save and cleared the dirty flag after any finished upload. Now preference updates are serialized across Activity instances; account generation/device identity invalidate queued work after disconnect/account changes, and a dirty revision preserves edits made during a network request. Each restore acknowledgement requires a matching verified download registered for the active account; a change during a download prevents offering that stale restore. Provider-side writes already in flight cannot be undone, and an edit after the download but before applying it still requires frontend/real-device validation. This does not introduce atomic Google Drive remote CAS or modify a live provider. Existing privacy/backup gates retained. Three structural regression checks, actual compilation and provider acceptance pending.
